# Git&GitHub 가이드 제작 기준서

> 기존 교재를 반복 개정하기 위한 AI 작업 기준

## 1. 목적
Git과 GitHub의 기본 기능을 복습하고, 저장소 생성·선택부터 Tag / Release 및 CI/CD까지 하나의 작업 사이클을 이해하고 재현하는 실습 자료를 유지·개선한다.

## 2. 문서명
- 학습자료: **Git&GitHub 가이드**
- 제작 기준 문서: **Git&GitHub 가이드 제작 기준서**

## 3. 편집 원칙
- 반드시 업로드된 기존 교재를 먼저 확인하고, 기존 내용을 가능한 유지한다.
- 요청받은 부분만 추가·수정한다. 전체 재작성, 불필요한 분량 증가, 목적 외 주제 확장을 하지 않는다.
- Git/GitHub 기능 자체를 중심으로 서술한다. 특정 언어, 업무 프로젝트, 개인 포트폴리오, 학습 기간을 전제하지 않는다.
- 개념은 짧게 설명하고 버튼 위치, 조작 순서, 결과 확인을 충분히 적는다.
- 가능하면 실제 GitHub Desktop·GitHub 화면 또는 기능 중심의 간단한 도식을 사용한다.
- 메뉴와 기능 설명은 공식 문서로 확인하며 모르는 부분은 임의로 보충하지 않는다.

## 4. 다룰 기능 범위
Repository 생성·선택·Clone → Changes / Commit → Push / Fetch / Pull → Branch → PR / Merge → 변경 취소 / 충돌 → Actions CI/CD → Tag / Release.

## 5. 실습 작성 방식
각 기능은 다음 순서로 작성한다.

1. 기능의 뜻
2. 실행 화면/메뉴
3. 클릭 또는 입력 순서
4. 확인할 결과

예제 저장소는 가능하면 하나만 사용하여 기능 간 연결을 유지한다.

## 6. 제외할 내용
특정 C# 서비스, 스크래핑 업무, Java 재구현, 포트폴리오 전략, 개인 이직 계획, 긴 학습 로드맵, 주제와 무관한 개발 아키텍처.

## 7. 향후 AI 개정 요청 형식
> 첨부한 Git&GitHub 가이드와 제작 기준서를 기준으로 ○○ 기능만 추가하거나 수정해 줘. 기존 구조와 설명은 유지하고, 수정된 부분을 알려줘.

## 8. 납품 기준
개정 PDF의 파일명은 **Git&GitHub 가이드.pdf**로 유지한다. 한글 글꼴 깨짐·잘림·빈 페이지를 확인하고, 변경한 부분만 간략하게 보고한다.
## 9. 개정 요청 (Change Requests)

### 2026-10-13 | Git/GitHub UI 이미지 보강

**대상 문서:** Git&GitHub 가이드.pdf  
**작업 상태:** 요청  
**작업 범위:** 기존 실습 단계별 UI 이미지 추가

**요구사항**

1. Git, GitHub 및 GitHub Desktop의 공식 문서를 참고하여 실습 내용에 적합한 UI 이미지를 확보한다.
2. 각 실습 단계의 설명과 직접적으로 연관된 위치에 이미지를 배치한다.
3. 이미지에는 해당 기능의 메뉴, 버튼 및 주요 조작 영역이 명확하게 표시되어야 한다.
4. 기존 교재의 목차, 설명 및 실습 흐름은 유지하며, 이미지 추가에 필요한 최소한의 편집만 수행한다.
5. 실제 UI 이미지를 우선 사용하고, 이미지 확보가 어려운 경우에는 임의의 화면을 실제 UI로 표현하지 않는다.

**적용 예시**

- 대상: `02. 저장소 생성 또는 기존 저장소 선택 > A. 새 저장소 만들기`
- 내용: GitHub Desktop의 저장소 생성 화면 추가
- 목적: 학습자가 설명과 실제 UI를 대조하여 실습할 수 있도록 개선

**완료 기준**

- 이미지와 실습 단계의 내용이 일치할 것
- 이미지 내 메뉴 및 텍스트를 식별할 수 있을 것
- 기존 본문의 누락이나 불필요한 변경이 없을 것
- PDF 출력 시 이미지 잘림 및 레이아웃 오류가 없을 것
